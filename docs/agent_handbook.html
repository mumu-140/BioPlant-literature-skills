bio-literature-digest · 使用手册

文献日报值班手册

一个面向生物学文献的双层流水线：Producer 每天抓取、过滤、分类、翻译并发出双语日报；Optimizer 读人工审核结果，保守地优化规则。本页覆盖安装、运行、审核、产物契约与 API/MCP 速查。

Python 3.10+ 时区 Asia/Shanghai · 每日 08:00 CST 窗口 覆盖前一自然日 00:00–24:00 单任务：同一时间只跑一个 run
01

认识项目

它把可配置的期刊关注清单变成一条每日流水线：优先官方 RSS / TOC / Advance 源，归一化元数据，过滤非生物内容，归入固定分类，产出中英双语摘要（中文标题、中文摘要、摘要、DOI、期刊、发表时间、链接），按时刻投递邮件并归档。

L1 Producer 抓取 feed→ 相关性过滤→ 固定分类→ 翻译 · 摘要→ 导出 CSV / XLSX / HTML→ 邮件 · 归档 · 审核快照
L2 Optimizer 人工审核 backlog→ AI 读审核结果→ 保守优化规则 / prompt / 来源

Producer 可以跨机器换实现，产物契约保持稳定（见 05）。优化器和调度器不绑定平台：Mac 用 launchd，Windows 用任务计划，检查和应用层优化交给 AI。

信息分层：三条铁律

信息按类型分层，不按目录喜好
层位置内容
公开源config/ · agents/ · docs/期刊源、分类规则、术语表、邮件/翻译/LLM 的模板形状（*.example.yaml）、runtime baseline
本机私有local/真实密钥、真实收件人、真实 SMTP、本机路径 override；永不提交
运行产物var/工作目录、归档、审核、日志、SQLite；程序生成，永不手工塞配置

真实密钥只允许出现在 local/.env.local。不要写进 config/、scripts/、测试或自动化文件；不要把真实邮箱、真实本机路径写进 .example.yaml。推送 GitHub 前先跑 scripts/audit_secrets.py。

02

安装与最短路径

手动安装

核心流水线只需 Python 3 和 PyYAML；远程 API 额外用 FastAPI、Uvicorn、httpx，均由 requirements.txt 覆盖。想以“技能包”形态给 Codex / Claude Code 用，把整个仓库放进 AI 的 skills 工作区，让 AI 直接读 SKILL.md、README.md、docs/user_quickstart.md、config/、scripts/（详见 08）。

首次初始化：从公开模板复制本机副本

只想先占位跑通时，最小集是去掉最后三行。模板里只放配置形状与环境变量名，真实值一律填在 local/ 副本里。

最短使用步骤

1 · 建 .venv安装依赖
2 · local/.env.local填真实密钥（翻译、SMTP、LLM）
3 · local/runtime/production.yaml按需改路径、时区、投递参数
4 · local/integrations/users.yaml收件人主名单
5 · local/integrations/email_config.yamlSMTP 参数（新增通道才改）
6 · config/content/journal_watchlist.yaml期刊源与抓取范围
7 · audit + runaudit_secrets → run_production_digest
03

日常运行

推荐生产入口

它会：以 production.example.yaml 为 baseline、叠加 local/runtime/production.yaml、加载 local/.env.local、调起 run_digest.py、生成附件与 HTML、发邮件、归档到 var/archives/daily-digests/YYYY-MM-DD/、同步每日审核快照到 var/reviews/daily-reviews/YYYY-MM-DD/、刷新 active backlog、并按 runtime 配置决定是否同步 SQLite。

窗口策略保持 delivery.window_policy: previous_day：只覆盖 delivery.timezone 下“前一自然日 00:00–24:00”。只有确认要旧行为（前一日 00:00 到发送时刻）时才改 previous_day_to_delivery。

04

审核与二次优化

人工审核的唯一权威文件是 var/reviews/backlog/review_backlog.xlsx。每一天的快照只是只读记录，改动都落在 backlog 上。

审核以确定性回退为前提：摘要失败的文章保留英文标题并留可重试占位符、分类不确定入 other、结果里保留 “研究了什么 / 得到了什么 / 对生物或 AI-for-bio 意味着什么” 三问的事实化摘要。

07

运维入口

  • macOS 定时：ops/launchd/ 下的 plist 模板 + scripts/generate_launchd_plist.py 从 runtime YAML 生成，不手改生成物；包装脚本是 scripts/run_production_digest_launchd.sh。
  • 便携发行包：只打包已提交的 Git HEAD，排除 local/、var/、venv、缓存与归档，并生成 SHA-256 校验。
  • SQLite 同步：scripts/sync_digest_db.py 入库 digest.csv、review_queue.csv、daily_review.csv 到 var/db/bio_digest.sqlite3，由 runtime YAML 开关控制。
  • 分层检查：check_project.py 统一入口；只定位结构层问题时可单独跑 check_harness.py 或 check_alignment.py。

生产环境 HTTPS API 的部署、systemd 与反向代理细节不在本页展开，见仓库 docs/https_api_deployment.md（覆盖拓扑 A/B、鉴权、systemd、Caddy 与验收清单）。

08

Agent 接入

AI 安装方式

把整个仓库放进 AI 工具的 skills 工作区，让它直接读取 SKILL.md、README.md、docs/user_quickstart.md、config/、scripts/。AI 安装不替代本机配置——真实运行时仍然要配置 local/。

SKILL.md 假说一CST 08:00 投递；窗口默认前一自然日 00:00–24:00，旧行为需显式指定
SKILL.md 假说二包含所有文章类型；QQ / 163 SMTP；摘要三问事实化，不自编结果
改前必读docs/engineering_harness.md（放置与保密契约）；改后跑 check_project.py

MCP（只读，stdio，共享 runs_service）

四个只读工具；不能发起 run、不发邮件。实现只用标准库，无 FastAPI 的主机也能跑。返回文本中订阅者邮箱一律掩码。

09

改动纪律

改任何脚本、配置、docs、调度资产或增删文件前，先读 docs/engineering_harness.md——它是本项目的放置与保密契约。改完统一跑：

验证清单（来自 SKILL.md）

  • 先用小期刊子集试跑；确认不相关材料、化学论文被过滤
  • 确认 AI 类期刊只留下生物学相关论文；重复 DOI 折叠为一条
  • 导出表含双语标题与中文摘要；人工审核 xlsx 可编辑
  • 所选 SMTP 通道真实发信成功；产物契约 nine 文件齐全
